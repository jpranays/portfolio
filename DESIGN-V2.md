# OPERATOR — redesign-v2 binding specification

The portfolio becomes working software: one app window with a titlebar, a command-input
hero, panel-and-row layouts, and a live status bar. The full design direction (typography,
palettes, accent system, layout, per-section blueprints, extras design, interactions,
anti-AI tactics, risks) is in **Part B** below — it is the law. Part A defines the
engineering contracts that make parallel implementation coherent.

## Part A — Engineering contracts

### A1. Global rules
- No gradient text, no glassmorphism, no glow shadows, no floating badges, no typing-loop
  hero, no 3D tilt, no marquee, no emoji in UI chrome. Elevation = border + surface tier;
  box-shadow only on overlays.
- Text floor 12px. Form inputs 16px. Viewport meta: `width=device-width, initial-scale=1` only.
- Every interactive element: 2px `var(--ap-ring)` focus-visible outline, offset 2px.
- Touch targets ≥40px. All overlays use the shared `useOverlay` primitive (A4).
- Numerals that carry data: `tabular-nums`. Live values get mono source-tags
  (e.g. `npm registry — live`) and degrade to floor constants stamped `as of 2026-07` —
  never spinners-forever, never zeros.
- Copy voice: changelogs and man pages. Eyebrows are mono paths (`~/work`). No "passionate",
  no "journey", no marketing adjectives.
- ALL current interactive extras survive, redesigned per Part B §EXTRAS. None silently deleted.

### A3. `src/config/metrics.js` — the anti-contradiction module
Every number quoted anywhere (components, index.html meta, JSON-LD) comes from here:
`NPM_WEEKLY_FLOOR = 25000` (display "~25K"), `OSS_MONTHLY = "10M+"`,
`PKG_FLOORS = { "react-fast-hooks": 20000, "cli-gh": 5000 }`, `AS_OF = "2026-07"`,
wins: `ATTACK_SURFACE = "−80%"`, `PAYMENT_SUCCESS = "+12%"`, `LOAD_TIME = "−35%"`,
`CHAT_SAVINGS = "$30K/yr"`, `RESOLUTION = "55%"`, `COVERAGE = "90%"`, `PR_COUNT = 9`.
Experience durations come from `utils/experience.js` (never hardcode years).

### A4. Cross-tree communication
App owns overlay state and passes handlers. Anything else crossing trees uses these
CustomEvents on `window` (names are law):
`portfolio:open-palette`, `portfolio:open-terminal`, `portfolio:open-shortcuts`,
`portfolio:set-accent` (detail: accent key), `portfolio:operator-unlock`,
`portfolio:resume-download`. Toasts via existing `useToast()` context.
Component contracts:
- `Titlebar({ onOpenPalette, theme, toggleTheme, activeSection })` — internal 7-tap monogram
  counter dispatches `portfolio:operator-unlock`; breadcrumb from activeSection; wordmark
  hover crossfades to mono `@jpranays` (aria-label constant).
- `StatusBar({ onOpenTerminal, onOpenShortcuts, musicPlaying, onToggleMusic })` — internally:
  useAccent + AccentPopover, useNpmStats readout, useAvailability, Pune clock (mono, per-minute),
  scroll progress (2px top-edge fill + % readout + velocity glyph), back-to-top after 100vh.
- `CommandPalette({ open, onClose, ...handlers })` — groups: Sections / Actions / Toys / Links.
- `TerminalOverlay({ open, onClose })` — commands: help, whoami, stack, work, oss, npm, prs,
  hire, email, resume, theme <light|dark>, accent <name>, clear, exit, konami.
- `AccentPicker.jsx` exports `AccentPopover({ open, onClose, anchorRef })` and re-exports useAccent.

### A5. Accent token matrix (globals.css)
`html[data-accent]` ∈ signal (default) | ion | photon | ember | pulse | mono.
Per accent × per theme define: `--ap-vivid`, `--ap-text`, `--ap-ring`, `--ap-on-accent`.
Derive washes with `color-mix(in oklab, var(--ap-vivid) 12%, transparent)` → `--ap-dim`,
and the calendar ramp steps similarly (10/25/45/70/100% mixes) — do NOT hand-declare ramps.
`mono` accent: `--ap-vivid`/`--ap-text` = text-primary; interactive states must also carry
underline/weight/border (non-color affordance test case). Hexes per Part B §ACCENT SYSTEM.
Neutral scale per Part B §PALETTE. Pre-paint script in index.html reads localStorage
`pj-theme`/`pj-accent` and sets `.dark` + `data-accent` before first paint.

### A6. Motion tokens
`--dur-fast:120ms; --dur-base:180ms; --dur-panel:240ms;` panel ease `cubic-bezier(0.32,0.72,0,1)`.
Section entrance: one-shot 12px rise + fade 320ms, 40ms row stagger, viewport-once.
Exactly ONE looping animation on the page: status-bar availability dot (2.4s).
Global reduced-motion CSS kill-switch + `useMotionPreference` in every effect.
Konami reduced-motion fallback toast: "You found it. Respect."

### A7. Judges' steal-ideas — ALL adopted
Mono source-tags under wins-strip numerals; `as of <date>` degradation tags; 7-day sparklines
on both npm panels; Pune clock in status bar; MONO sixth accent; titlebar wordmark crossfade;
footer konami tease `↑ ↑ ↓ ↓ … you know the rest` (aria-hidden); ⌘K nudge fires once on first
scroll-past-hero (not idle timer; pointer-aware copy); terminal `hire` + `prs` commands;
color-mix accent derivation; square crosshair ClickBurst; now-playing track name in status-bar
readout + terminal `whoami` while music plays; konami payoff choreography (titlebar → rail →
status bar flash in sequence before scanlines).

# Part B — The OPERATOR direction (verbatim from the winning design panel)

=== PHILOSOPHY ===
The site is not a page about a developer tool builder — it IS the tool: a single app "window" with a titlebar, a command input where the hero headline usually goes, panel-and-row layouts, and a live status bar across the bottom. A visitor lands inside working software: they can click the command input, type "oss", and jump — the Cmd+K palette, terminal, and accent picker stop being easter eggs and become the product's visible controls. For a PCI-DSS checkout owner and npm author, this is self-evidencing: the craft claim ("I build precise, dense, reliable interfaces") is proven by the medium itself, and every number on screen is live, owned by exactly one section, and set in tabular numerals like real telemetry.

=== INSPIRATIONS ===
Raycast (command-row anatomy, kbd chips, launcher-as-hero) | Linear (hairline borders, surface tiers, 120-240ms motion discipline, cursor-tracked border glow) | Vercel / Geist design system (neutral graphite scale, tabular numerals, flat panels) | Warp terminal (bottom-docked terminal panel, block-based output) | GitHub Primer (list-row density, contribution calendar as first-class data, AA-verified accent scales) | Notion Calendar / Cron (the status bar as a signature: availability, clock, tiny live readouts) | Arc (playful chrome details — boot moment, unlockable 'operator mode' — inside strict app chrome)

=== TYPOGRAPHY ===
DISPLAY: Geist (Google Fonts, variable 400–700). Display/headings at 600–650; the metric numerals at 650 with font-feature 'tnum'. Loaded as one variable file, latin subset, display=swap.
BODY: Geist 400/500 for all prose and UI labels. No second sans — hierarchy comes from size, weight, and the two text tiers, never from font-family swaps.
MONO: Geist Mono (Google Fonts, 400–500 only — hard cap at 500 per the bold-mono audit finding). Usage contract: literal code, install commands, package/repo/PR names, versions, kbd chips, status-bar readouts, and the ~/path eyebrows. Dates, tooltips, labels, copyright are Geist sans — this scarcity is what makes the mono moments read as 'instrument'.
SCALE: h1: clamp(2rem, 1.2rem + 3.2vw, 3.25rem) (32→52px), weight 650, line-height 1.1, tracking -0.02em — deliberately smaller than the old 72px hero; the console idiom is dense, not billboard. h2 section heads: 24px/1.25 mobile → 28px lg, weight 600, tracking -0.01em. h3 entry titles: 18px/1.4 weight 600 (ONE consistent size site-wide). h4 card/panel titles: 16px/1.45 weight 500. Body prose: 16px/1.65 Geist 400, max-width 65ch always (never removed at breakpoints). Meta/labels: 13px/1.5 Geist 500 in --text-secondary. Mono readouts + chips: 13px; kbd chips 12px. HARD FLOOR: 12px — text-[10px]/text-[11px] are deleted from the codebase and linted against. Metric numerals: clamp(2rem, 1rem + 2.5vw, 2.75rem) Geist 650, tabular-nums, accent text color. Eyebrows (~/work): Geist Mono 500, 13px, letter-spacing 0.02em, --text-secondary. Viewport meta ships as width=device-width, initial-scale=1 (no maximum-scale/user-scalable); all form inputs are 16px so iOS never auto-zooms; the whole scale verified at 200% zoom / 320px reflow.

=== PALETTE LIGHT ===
Cool paper-free neutral (no warm cream — that was Broadsheet's). bg-base #FAFAFB; surface-0 (titlebar/statusbar) #FFFFFF at 92% + saturate(1.4) backdrop; surface-1 (panels) #FFFFFF; surface-2 (hover/inset rows, code blocks) #F4F4F5; border-hairline #E4E4E7; border-strong (panel outlines, focus-adjacent) #D4D4D8; text-primary #18181B (16.4:1); text-secondary #52525B (7.6:1); text-tertiary #6E6E76 (4.7:1 — the legal floor, used only for timestamps/fine print ≥13px). Accent applies to: filled primary buttons (accent bg + white text, per-accent hexes chosen for ≥4.5:1), metric numerals and inline links (--ap-text tier), active nav/section-index item, focus rings (--ap-ring, ≥3:1 vs bg), the 2px scroll-progress fill, availability-adjacent chips (10% alpha --ap-dim washes), and the cursor-tracked border glow. Accent never exceeds ~5% of any viewport — everything else is the neutral scale, which is what lets five accents coexist. Semantic colors are fixed and separate from the accent: success #059669, danger #DC2626.

=== PALETTE DARK ===
Pure neutral graphite — zero blue cast, explicitly not the old navy #060610. bg-base #0C0C0D; surface-0 (titlebar/statusbar) #101012 at 88% + saturate(1.4); surface-1 (panels) #131316; surface-2 (hover rows, inset code) #1A1A1F; border-hairline #26262B; border-strong #35353B; text-primary #FAFAFA (17.9:1); text-secondary #A1A1AA (7.9:1 on surface-1); text-tertiary #7E7E89 (4.9:1 on surface-1 — floor tier, ≥13px, never for real content below that). No glassmorphism, no glow shadows, no gradient text: elevation is border + surface tier only; box-shadow exists solely on overlays (palette, popovers: 0 16px 48px rgb(0 0 0 / 0.5)). Dark is the default (matches inline head script + meta theme-color #0C0C0D so html class, theme-color, and the useTheme fallback finally agree). Accent roles identical to light but use the vivid tier (--ap-vivid) for numerals/links since dark surfaces afford brighter hues. Contrast floor enforced in CI via axe: nothing below 4.5:1 may carry information; slate-600/700-equivalents are reserved for aria-hidden decoration only.

=== ACCENT SYSTEM ===
Architecture: html carries data-accent="signal|ion|photon|ember|pulse" (+ .dark class). globals.css defines, per accent × per theme, exactly five tokens — --ap-vivid (graphics, numerals in dark), --ap-text (AA-safe text/links tier), --ap-dim (10–12% alpha wash for chips/active rows), --ap-ring (focus ring, verified ≥3:1 against both bg and surface-1), --ap-on-accent (text on filled buttons). Components reference ONLY these tokens — no orange-* literals, no runtime <style> injection, no !important remapping; the entire current injectStyle() liability disappears. The five accents (dark-vivid / light-text): Signal green #3ECF8E / #047857 (DEFAULT — the site's signature; terminal-native, availability-coded); Ion blue #58A6FF / #0969DA; Photon violet #A78BFA / #6D28D9; Ember amber #FBBF24 / #A16207 (the nod to the old orange, demoted to an option); Pulse magenta #F472B6 / #BE185D. Filled-button text: near-black #0C0C0D on all dark vivids (≥7:1), white on all light text-tier hexes (≥4.7:1) — every pair pre-verified so a visitor can never pick an inaccessible combination. Harmony strategy: all five vivids sit at similar OKLCH lightness (~0.75–0.8) and chroma, and the accent's surface area is capped (<5% of viewport, one accent element per panel max), so swapping hue never changes the design's balance. Picker UI (the fix for the fake AccentPicker): (1) a swatch button in the status bar opening a popover of 5 labeled radio swatches with names + kbd 1–5, (2) a 'Change accent' submenu in the command palette, (3) `accent <name>` in the terminal. Choice persists to localStorage pj-accent and is applied pre-paint by the same inline head script that resolves theme; picking triggers ONE 400ms CSS-variable transition. The setInterval auto-cycle is deleted. Under prefers-reduced-motion the swap is instant. GitHub calendar and all live-data theming read the same tokens, so an accent pick re-themes the heatmap once, on demand.

=== LAYOUT ===
The window metaphor gives the page fixed chrome at exactly two edges — titlebar (48px, top) and status bar (36px desktop / 40px + safe-area touch, bottom) — and NOTHING else fixed in corners (this replaces today's four-corner pileup of music/back-to-top/toasts/dots). Content container: max-w-[1120px], px-5 sm:px-8, on a 12-col grid at lg. Asymmetry strategy: the instrument look forbids uniform 3-up card grids; each section uses an 8/4 or 7/5 split (content column + live/aux panel) or full-width list rows — at most one symmetric pair per page (the two npm package panels). Section index rail: at xl+, a 176px sticky left rail (grid col) lists sections as text rows (~/work, ~/ships…) with an accent bar on the active item — this is SectionDots, promoted from anonymous dots to a labeled minimap; below xl it disappears (the palette + status bar cover navigation), freeing the gutter collision the audit found at 1024–1240px. Vertical rhythm: sections are separated by hairline borders that span the content column (real delimiters, not floating dividers in voids) with py-16 lg:py-20 for dense data sections (work, ships, upstream) and py-20 lg:py-28 only for hero and contact; header→body gap fixed at 48px, group→group 40px, related-row→row 8px, everywhere. Card/panel primitive: 1px border-hairline, radius 8px (10px for overlays), two padding tokens only — panel-sm p-4 (rows, stats) and panel-lg p-6 (feature panels) — encoded in the component API. Breakpoints: mobile-first single column; md (768) introduces 2-col splits and the titlebar breadcrumb; lg (1024) activates the 12-col grid and hero live panel; xl (1280) adds the section rail. Toasts: bottom-center, 12px above the status bar — no fixed control is ever occluded. Fixed chrome map is a documented contract: titlebar top / rail left (xl) / status bar bottom / toasts bottom-center — four zones, zero overlaps.

=== INTERACTIONS ===
Motion language: 'instrument calm' — the UI responds, it never performs. Tokens: --dur-fast 120ms (hover bg, chip states), --dur-base 180ms (buttons, icon morphs, ease-out), --dur-panel 240ms (popovers, terminal dock, cubic-bezier(0.32, 0.72, 0, 1)), palette open 160ms scale 0.98→1 + fade. Section entrances: one-shot 12px rise + fade, 320ms, 40ms stagger between rows, viewport-once — never re-fires. Hover states: rows shift to surface-2 (bg only, no transform); buttons darken/lighten one tier; press = scale 0.98 at 120ms; panels never lift or tilt (3D tilt-cards are gone). Focus: 2px --ap-ring outline, 2px offset, ≥3:1, on absolutely everything interactive — since the accent drives the ring, focus is part of the personalization. What loops: exactly one element — the status-bar availability dot (2.4s). What stays static: all numerals after their single 600ms count-up on first reveal, the calendar, all chrome. Live-data updates swap values with a 180ms crossfade, no odometer loops. Reduced motion: a single useMotionPreference hook consumed by every effect (palette, terminal dock, confetti, ripple, EQ bars, count-ups, cursor glow, smooth scroll) PLUS the global CSS kill-switch (@media (prefers-reduced-motion: reduce) { *, ::before, ::after { animation-duration: .01ms !important; transition-duration: .01ms !important } html { scroll-behavior: auto } }) as the safety net — the site is fully usable and still handsome with motion at zero.

=== ANTI-AI ===
The AI-portfolio tropes are structurally impossible here: no gradient-clipped shimmer name, no typing-loop identity, no floating badge cloud, no glassmorphism, no 3-up icon-chip stat cards, no emoji badges, no 'passionate developer' copy. Replacements that read hand-built: (1) real app chrome — a titlebar breadcrumb that tracks scroll and a status bar with live npm telemetry is not in any template; (2) the hero is a command input, not a headline stack; (3) density over decoration — Raycast-anatomy list rows with right-aligned tabular meta, hairline borders, 8px radii; (4) every number is live, tabular, and owned by exactly one section, with fallbacks and meta generated from one constants module (claims can never contradict); (5) every skill carries a receipt link to its evidence — an unfakeable pattern; (6) copy voiced like changelogs and man pages: '~/work', 'status --live', 'stack --receipts', '9 PRs merged into libraries you probably use'; (7) restraint as signature: one loop, one accent element per panel, accent <5% of viewport; (8) craft tells only engineers notice — descender-safe reveal masks, kbd chips at true AA, tabular-nums everywhere, safe-area-aware status bar, scoped context menu; (9) the easter-egg economy (operator mode, terminal commands, tap-konami) rewards exploration instead of front-loading spectacle.

=== RISKS ===
1) The status bar costs 36–40px of mobile viewport forever — mitigate with 40px max height, safe-area padding, and trimming it to 4 controls on small screens; test on iPhone SE. 2) A hero that looks like an input could confuse non-technical visitors (recruiters) — it's a real <button> with visible label text, a search glyph, and the CTAs sit directly beneath, so the traditional path is never blocked; usability-test the first 5 seconds. 3) Neutral graphite + green + contribution calendar can drift toward 'GitHub cosplay' — the titlebar/status-bar frame, Geist (not Mono-heavy Primer styling), and the five-accent system keep it distinct; avoid GitHub's exact #0D1117. 4) Dense rows may under-sell to skimmers — the wins strip's three large numerals and the two package panels guarantee scannable peaks every ~1.5 viewports. 5) Five swappable accents × 2 themes = 10 contrast matrices — locked down by pre-verified token pairs and an axe/contrast CI gate so regressions can't ship. 6) Geist variable font weight range costs ~45KB woff2 — subset latin, load 400–700 sans + 400–500 mono only, font-display swap; still lighter than Inter+JetBrains at 5 weights. 7) Breadcrumb scroll-sync can jitter at section boundaries — hysteresis via rootMargin -40% on the section observer. 8) Deleting Skills/marquee/badges removes 'keyword surface' some ATS-minded visitors expect — the stack-with-receipts panel plus per-role tech chips preserve every keyword in higher-value form. 9) Terminal-dock + palette + context menu are three overlays sharing focus-trap logic — build one useOverlay primitive (trap, restore, Escape, scroll lock, inert siblings) so a11y is provably uniform instead of per-component best-effort.
